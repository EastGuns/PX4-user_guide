# Task3 클릭 라벨러 — 팀원용 안내

`click_labeler.html` 한 파일로 돌아가는 반자동 라벨링 도구입니다. 설치할 것이 없고, 영상이나 이미지 zip을 넣고 "자동 라벨링"으로 1차 패스를 돌린 뒤 틀린 것만 고치거나, 물체를 클릭해서 박스와 클래스(색_종류)를 만듭니다. 결과는 기존 자동 라벨러와 같은 YOLO 구조(images/labels/data.yaml)로 저장되고, Roboflow에 바로 올릴 수도 있습니다.

가장 빠른 흐름: **zip 선택 → 자동 라벨링 → 프레임 넘기며 틀린 박스만 고침 → zip 저장 또는 Roboflow 업로드.**
학습까지: **GPU PC에서 `학습서버_시작.bat` 실행 → 열린 페이지의 패널 6에서 Roboflow zip 선택 → 학습 시작 → Hailo 번들 zip을 Ubuntu로.** (4장)

## 1. 열기

- `click_labeler.html`을 Chrome 또는 Edge로 엽니다 (더블클릭). 인터넷 없이도 라벨링과 zip 저장은 됩니다. Roboflow 업로드만 인터넷이 필요합니다.
- 영상은 mp4(H.264)이면 됩니다. 브라우저가 열지 못하는 코덱이면 안내 문구가 뜨니 mp4로 변환해서 다시 넣으세요.
- 라벨은 브라우저에 자동 저장됩니다. 창을 닫았다 다시 열고 같은 영상을 고르면 "이전 작업 복원" 버튼이 나옵니다.

## 2. 사용 순서

1. **불러오기**: 왼쪽 패널 1번에서 영상 파일을 고르거나, **이미지가 든 zip**(폴더 깊이 상관없음, images/labels 구조의 YOLO zip도 됨)을 고릅니다. zip 안에 `labels/*.txt`가 있으면 기본으로 같이 불러옵니다(체크 해제 가능). 이미 잘라 둔 이미지 여러 장을 직접 골라도 됩니다. zip은 브라우저 안에서 풀리므로 50 MB 정도(245장)는 몇 초면 됩니다.
2. **프레임 자르기**: 간격(초) / 초당 N장 / 총 N장 중 하나를 고르고 값을 넣으면 예상 장수가 보입니다. 필요하면 시작·끝 시각을 좁히세요. "프레임 추출 시작"을 누르면 원본 해상도 그대로 JPEG로 잘립니다. (기본값 0.5초 간격 = 2 fps, 기존 데이터와 같은 간격)
3. **자동 라벨링(1차 패스)**: 패널 3번 맨 위 "자동 라벨링" 버튼. 모든 프레임에서 패드(진한 페인트 덩어리 → 원 맞춤 → 그림자 보강)와 그 위의 캔(다른 색 캔은 색상대로, 같은 색 캔은 어두운 덩어리에서 그림자를 떼어내서)을 찾습니다. 245장에 약 2분. 끝나면 프레임을 넘기며 틀린 박스만 고치면 됩니다. 한 프레임만 다시 돌리려면 `A`. "?"가 붙은 점선 박스는 자신 없는 것이니 꼭 확인하세요.
   - 기존 2fps 라벨 245장(1,805박스)과 비교한 자동 패스 성적(IoU 0.5 기준): 전체 정밀도 0.975 / 재현율 0.969. 클래스별 정밀도/재현율: Blue_Rag 0.97/1.00, Blue_Tin 0.97/0.99, Green_Rag 0.96/0.96, Green_Tin 0.98/0.93, Red_Rag 0.96/0.99, Red_Tin 1.00/0.97. 못 잡는 것: 화면 가장자리에서 잘린 패드의 얇은 조각, 드론 그림자 속 캔, 프레임 가장자리에 걸친 캔, 착륙 다리(빨강)가 패드로 잡히는 경우 가끔.
4. **클릭 라벨링(고치기)**:
   - `T` = Tin(캔) 모드, `R` = Rag(패드) 모드. 모드에 맞춰 물체 위를 **한 번 클릭**하면 HSV로 영역을 키워 박스를 만들고, 색(Red/Green/Blue)을 자동으로 판정합니다. 클래스는 색_종류(예: Green_Tin).
   - 패드는 캔이 아닌 **페인트 부분**을 클릭하세요. 캔은 캔의 가운데를 클릭하세요.
   - 박스가 틀리면 모서리/변을 드래그해 고치고, 안쪽을 드래그하면 옮깁니다. 우클릭하면 지웁니다. 박스 목록의 드롭다운에서 클래스를 바꿀 수 있고, 박스를 선택한 뒤 `1`/`2`/`3`을 누르면 Red/Green/Blue, `Q`를 누르면 Tin↔Rag.
   - 자동 탐지가 안 되는 곳은 `Shift+드래그`로 직접 박스를 그리면 됩니다(색은 박스 안을 보고 자동 판정).
   - 마우스 휠로 커서 위치를 중심으로 확대/축소(최대 16배), 휠을 누른 채 드래그하거나 `Alt`+드래그로 화면 이동, `0`으로 원래 크기. 확대한 채로 모서리를 잡아 미세 조정하면 됩니다. 확대 배율은 프레임을 넘겨도 유지됩니다.
   - `←`/`→`로 프레임 이동, `C`로 이전 프레임 박스를 가져와서 현재 프레임에 재탐지, `Ctrl+Z` 되돌리기. "미라벨로" 버튼은 아직 라벨 없는 다음 프레임으로 갑니다.
   - 점선 박스에 "?" 표시가 있으면 자동 탐지가 자신 없는 박스입니다. 확인하고 고치세요.
5. **내보내기**: "YOLO zip 저장"을 누르면 `영상이름_labels.zip`이 내려옵니다. 압축을 풀면 `images/`, `labels/`, `data.yaml`, `classes.txt`가 있고, `tools/task3_train`이나 Roboflow에 그대로 씁니다. 라벨 없는 프레임은 기본적으로 빠집니다.
6. **Roboflow 업로드**: Private API Key(Roboflow → Settings → API Keys, 세션 동안만 브라우저가 기억), 프로젝트 ID(기본 `my-first-project-ns7ou`), 배치 이름, split을 넣고 "라벨된 프레임 업로드". 이미지와 라벨이 함께 올라가고, 실패하면 Roboflow가 돌려준 오류 문구가 그대로 보입니다. 올라간 뒤 Roboflow의 Annotate 탭에서 배치를 확인하고 데이터셋에 넣으세요. API Key는 절대 파일·채팅·저장소에 남기지 마세요.

## 3. 점검 영상과 Claude 연동

1. 패널 5번 "점검 모드 켜기" → "재생". 박스가 그려진 프레임이 왼쪽 아래 프레임 번호와 함께 정한 속도(fps)로 재생됩니다. `Space`로 재생/정지.
2. 이상한 것이 보이면 화면을 클릭하면 멈춥니다. 다시 그 지점을 클릭하면 노란 핀이 생기고, 무엇이 이상한지 적고 Enter. 핀은 목록에 쌓이고, 목록을 클릭하면 그 프레임으로 갑니다.
3. "메모+이미지 내보내기 (zip)" → `영상이름_review_notes.zip`. 안에는 메모(JSON: 프레임 번호, 좌표, 내용, 그 프레임의 현재 박스), 핀 주변 3배 확대 이미지, 원본 프레임, 박스 그린 프레임, 현재 YOLO 라벨 txt가 들어 있습니다.
4. 그 zip을 Claude 프로젝트 스레드에 올리고 "review_notes.json의 메모를 분석해서 labels/*.txt를 고쳐줘"라고 쓰면 Claude가 원인을 분석하고 고친 라벨 txt를 돌려줍니다.
5. 돌아온 txt들을 "수정된 라벨 txt 가져오기"로 선택하면 같은 이름의 프레임에 덮어써집니다. 그 다음 다시 zip 저장 또는 Roboflow 업로드.
6. 영상 파일이 필요하면 "점검 영상 WebM 저장"을 누르세요. 실시간 속도로 녹화되므로 영상 길이만큼 걸립니다 (예: 245프레임 2 fps → 약 2분).

## 4. PC에서 학습 (패널 6)

브라우저만으로는 GPU 학습을 못 하므로, 학습은 PC에서 켜는 작은 서버(`trainer/task3_train_server.py`)가 맡습니다. 라벨링과 따로 써도 됩니다.

1. GPU PC(아나콘다 base에 CUDA용 torch와 ultralytics가 있는 PC)에서 `학습서버_시작.bat`을 더블클릭합니다. 검은 창이 뜨고, 브라우저에 라벨러가 `http://127.0.0.1:8765` 주소로 열립니다. 패널 6 맨 위에 GPU 이름이 보이면 준비된 것입니다. **이 창을 닫으면 서버와 진행 중인 학습이 함께 끝납니다.**
2. 패널 6의 "Roboflow zip 선택"에서 Roboflow → Versions → Download Dataset → **YOLOv11** 형식으로 받은 zip을 고릅니다. "점검용 원본 영상"에 Task3 원본 영상을 넣으면 학습 뒤에 박스와 프레임 번호를 그린 점검 영상도 만듭니다(선택).
3. 에폭(기본 100)과 배치(기본 8)를 확인하고 "학습 시작". 단계별 진행, 에폭마다 mAP 그래프, 남은 학습 시간이 보입니다. "중지"로 언제든 멈출 수 있습니다.
4. 끝나면 valid/test 클래스별 P/R/mAP 표와 파일 링크(Hailo 번들 zip, 가중치 .pt, ONNX, 점검 영상, REPORT.md)가 나옵니다. "폴더 열기"를 누르면 결과 폴더(`train_runs/runs/날짜_시각_v버전/`)가 탐색기로 열립니다. 페이지를 새로 고치거나 서버를 다시 켜도 마지막 결과가 다시 보입니다.
5. `task3_hailo_bundle_v버전.zip`을 Ubuntu Hailo PC로 옮겨 풀고 `bash hailo/compile.sh task3_yolo11n_v버전.onnx calib1024 hailo10h`를 실행합니다. 나온 `hef_out/tin_detector.hef`를 파이의 `~/models/tin_detector.hef`로 교체합니다(기존 파일은 백업).

서버가 하는 일 (레시피는 `tools/task3_train/train.py`와 같습니다):
- zip을 풀고 data.yaml의 클래스가 드론 노드 순서(Blue_Rag, Blue_Tin, Green_Rag, Green_Tin, Red_Rag, Red_Tin)인지 확인합니다. 순서만 다르면 라벨 번호를 고쳐 쓰고, 모르는 이름(예: Red_Pad)이 있으면 학습하지 않고 멈춥니다. Roboflow의 train/valid/test 분할은 그대로 씁니다.
- COCO 사전학습 `yolo11n.pt`에서 imgsz 640, hsv_h 0.005(색이 곧 클래스), flipud/fliplr 0.5, degrees 10, mosaic으로 학습합니다. GPU가 있으면 GPU를 씁니다.
- valid/test 평가 → (점검 영상, conf 0.4) → ONNX(opset 11, NMS 없음, Hailo end node 확인, .pt와 출력 대조) → 배포와 같은 640 letterbox 보정 이미지 1024장 → 번들 zip(ONNX + calib1024 + hailo/compile.sh + REPORT.md + 컴파일 안내).
- 처음 한 번은 `yolo11n.pt`(약 5 MB)를 내려받으므로 인터넷이 필요합니다. 같은 zip이나 영상을 다시 고르면 PC에 이미 있는 사본을 써서 바로 시작합니다.
- 다른 파이썬을 쓰려면 `T3_PYTHON` 환경변수에 python.exe 경로를 넣고 bat을 실행하세요. 맥/리눅스는 `python trainer/task3_train_server.py`.
- 서버는 이 PC의 브라우저(127.0.0.1)에서만 열리고, 다른 사이트의 요청은 받지 않습니다. 아티팩트 미리보기 창이나 파일로 연 페이지에서는 패널 6이 안내만 보여 줍니다.
- Roboflow의 "Train Model" 대신 이 패널을 씁니다. 여기서 학습하면 hef로 바꿀 .pt, ONNX, 보정 이미지가 바로 PC에 남습니다.
- 점검 영상 단계가 실패해도(코덱 문제 등) 그 단계만 건너뛰고 ONNX와 번들은 끝까지 만듭니다.

## 5. 자동 탐지가 하는 일과 한계

- 자동 1차 패스(autolabel.py를 단순화해 JS로 옮긴 것): 색마다 진한 페인트(S≥235, V≥110) 덩어리를 찾아 모양(채움비·종횡비·크기·착륙 다리 코너)을 거르고, 덩어리 위 한 점에서 클릭 탐지기(원 맞춤 + 그림자 보강)를 돌려 패드 박스를 만듭니다. 같은 색 덩어리는 한 패드로 합치고, 다른 색 패드 안의 작은 덩어리는 캔으로 돌립니다. 캔은 패드 원 안에서 (a) 다른 색상대의 채도 높은 작은 덩어리, (b) 패드와 같은 색이지만 페인트의 45% 이하로 어두운 덩어리를 찾습니다. (b)는 캔+그림자이므로, 다른 색 캔에 붙은 어두운 덩어리에서 그 프레임의 해 방향을 배우고, 그 반대쪽 끝의 둥근 부분만 캔으로 자릅니다(해 방향 정보가 없으면 "?"로 표시).
- 색 판정 HSV(OpenCV 스케일, H 0–179): Red 0–12/165–179, Green 40–90, Blue 95–135. 기존 `autolabel.py`와 같은 값입니다.
- 패드: 클릭 지점에서 진한 페인트(S≥235, V≥110)만 먼저 키운 뒤, 그 영역에 맞춘 원 안에서만 그림자 부분(S≥200, V≥60)을 보강합니다. 그래서 드론 그림자 아래의 푸르스름한 바닥으로 새지 않습니다.
- 캔: 클릭 지점 밝기를 기준으로 같은 색상대를 키웁니다. 패드와 같은 색 캔은 밝기 하한을 두어 캔의 그림자를 잘라냅니다. 캔 최대 크기(기본 120 px)보다 커지면 더 엄격하게 다시 시도하고, 그래도 안 되면 24 px 박스를 "?"로 만듭니다.
- 검증 결과(기존 자동 라벨 245프레임 중 601박스를 같은 지점 클릭으로 재현): Tin IoU 중앙값 0.89(0.5 이상 98%), Rag 0.99(0.5 이상 99%), 색 판정 598/601 일치.
- 잘 안 되는 경우: 화면 가장자리에서 잘리고 그림자까지 진 패드(박스가 짧게 나옴), 10 px짜리 아주 먼 캔(옆 캔 색으로 판정될 수 있음), 자기 그림자가 큰 캔(한쪽이 조금 잘림). 모두 드래그로 바로 고칠 수 있습니다.

## 6. Claude에게 줄 프롬프트 (같은 도구를 다시 만들거나 확장할 때)

아래를 그대로 붙여 넣으면 됩니다.

```
브라우저에서 설치 없이 돌아가는 반자동 YOLO 라벨링 도구를 HTML 파일 하나로 만들어 줘.

목적: 드론 하향 카메라 영상에서 색깔 캔(Tin)과 둥근 색깔 패드(Rag)를 라벨링한다.
클래스는 이 순서로 고정: Blue_Rag, Blue_Tin, Green_Rag, Green_Tin, Red_Rag, Red_Tin (data.yaml names 순서와 같아야 함).

입력:
- 이미지가 든 zip(폴더 깊이 무관, images/labels 구조의 YOLO zip 포함)을 브라우저 안에서 풀어(DecompressionStream deflate-raw, 외부 라이브러리 없이) 프레임으로 나열한다. zip 안의 labels/*.txt는 선택적으로 함께 불러온다.
- 사용자가 영상 파일(mp4)을 선택하면 길이·해상도를 보여주고, 사이드 패널에서 자르기 방식(간격 초 / 초당 N장 / 총 N장)과 시작·끝 시각을 입력받아 예상 장수를 보여준다.
- "추출" 버튼을 누르면 video 요소와 canvas로 원본 해상도의 JPEG 프레임을 만든다(파일명 영상이름_0001.jpg …). 이미 잘라 둔 이미지 여러 장도 바로 불러올 수 있어야 한다.

자동 1차 패스("자동 라벨링" 버튼, 모든 프레임 또는 라벨 없는 프레임만):
- 패드: 색마다 진한 페인트(S≥235, V≥110, 패드 색상대) 4-연결 덩어리를 찾고, 채움비(비가장자리 ≥0.5, 가장자리 ≥0.3)·종횡비(≤2.5, 가장자리 ≤10)·최대 크기·착륙 다리 코너(위쪽 20%·바깥 15%, 또는 빨강이 위 8% 안에서 바깥 35%에 있고 140 px 미만)로 거른 뒤, 덩어리 중심 근처 한 점에서 클릭 패드 탐지기를 돌린다. 같은 색 박스는 겹치거나 15 px 이내면 하나로 합치고(패드는 색당 하나), 다른 색 패드 안에 80% 이상 들어간 작은 덩어리는 캔 후보로 돌린다. 최대 변이 45 px 미만이면 패드가 아니다.
- 캔: 패드의 맞춤 원 안에서 (a) 다른 색상대, S≥200, 면적≥20, 채움비≥0.4, 종횡비≤2.2, 중앙값 S≥225인 덩어리 → 클릭 캔 탐지기로 박스 정제. (b) 패드와 같은 색상대, S≥200, 4≤V≤0.45×페인트 V인 덩어리(면적≥10, 채움비≥0.3, 둘레 띠의 60% 이상이 밝은 페인트, 최대 변이 패드 지름의 7% 이상). 다른 색 캔에 닿은 (b) 덩어리는 그 캔의 그림자이며, 그 중심 방향들의 면적 가중 평균이 그 프레임의 해 방향(단위벡터)이 된다. 나머지 (b) 덩어리는 해 방향에 투영해 먼 쪽 끝에서 지름(수직 범위, 반복 측정)만큼만 캔으로 자르고, 해 반대쪽으로 같은 색상대·V≤0.75×페인트 V인 밝은 면까지 박스를 늘린다. 해 방향이 없으면(직전 프레임 것도 없으면) 덩어리 전체를 "확인 필요"로 넣는다.
- 결과 박스: 변 5 px 미만, 종횡비 2.2 초과, 최대 캔 크기의 1.2배 초과는 버리고, IoU 0.3 이상 겹치면 하나만 둔다.

라벨링:
- 프레임을 하나씩 캔버스에 보여준다. Tin/Rag 모드(T/R 키)에서 물체를 클릭하면 HSV 영역 성장으로 박스를 만들고 색을 자동 판정해 클래스 = 색_종류로 넣는다.
- HSV는 OpenCV 스케일(H 0–179, S/V 0–255). 색 판정 색상대: Red 0–12 및 165–179, Green 40–90, Blue 95–135.
- 패드: 클릭점에서 진한 페인트(S≥235, V≥110, 패드 색상대 Red 0–8/170–179, Green 45–80, Blue 106–130)만 먼저 성장시키고, 그 영역의 경계점으로 원을 맞춘 뒤 원 안에서만 S≥200, V≥60으로 그림자 부분을 보강한다. 그림자 진 바닥은 푸르고 채도가 높으므로 원 밖으로 새면 안 된다.
- 캔: 클릭점 3×3 밝기 중앙값 sV를 기준으로 같은 색상대·S≥120·V≤sV+max(30, 0.8·sV)로 성장시키고, 결과가 최대 크기(기본 120 px)를 넘거나 창 경계에 닿으면 더 엄격한 조건으로 재시도한다. 캔이 패드와 같은 색이면 V≥0.5·sV 하한을 두어 캔의 그림자를 떼어낸다. 실패하면 24 px 박스를 "확인 필요" 표시로 만든다.
- 단축키 A: 현재 프레임만 자동 라벨링 다시.
- 박스 수정: 모서리/변 드래그로 크기, 안쪽 드래그로 이동, 우클릭 삭제, Shift+드래그로 수동 박스(색은 박스 안 색상 투표), 1/2/3으로 색 변경, Q로 Tin↔Rag, C로 이전 프레임 박스를 가져와 재탐지, Ctrl+Z 되돌리기, 돋보기(커서 주변 4배), 마우스 휠로 커서 중심 확대/축소(최대 16배)와 휠 드래그·Alt+드래그 이동, 0 키로 원래 크기(프레임을 넘겨도 배율 유지).
- 라벨은 localStorage에 자동 저장하고, 같은 영상을 다시 고르면 복원할 수 있어야 한다.
```
